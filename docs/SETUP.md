## 1. Why This File Exists

The repository does not ship with processed data or trained models.
Those are regenerable artifacts. They are intentionally excluded from
version control so the repository stays small and every teammate
reproduces the same pipeline from the same raw inputs.

This means: after cloning, you cannot run training. You must first
generate the processed data.

The steps below walk you from a clean clone to a state where you can
run your assigned cells.

## 3. Setup Steps

### Step 1 — Clone the Repository

```powershell
git clone https://github.com/Dustin-Martinez/network-guardian-ids.git
cd network-guardian-ids
```

Expected: the command completes with no error, and the current
directory is `network-guardian-ids`.

Verify:

```powershell
Get-Location
```

Expected output: a path ending in `\network-guardian-ids`.

---

### Step 2 — Confirm Python 3.11.9 Is Available

```powershell
py -3.11 --version
```

Expected output:

```
Python 3.11.9
```

If this prints a different version, or fails with an error, do not
continue. Install Python 3.11.9 from python.org and retry.

---

### Step 3 — Create the Virtual Environment

```powershell
py -3.11 -m venv .venv
.venv\Scripts\activate
```

Expected: the prompt now begins with `(.venv)`.

Verify the interpreter inside the venv:

```powershell
python --version
```

Expected output:

```
Python 3.11.9
```

If it prints a different version, deactivate, delete `.venv`, and
repeat Step 3 with the correct `py -3.11` interpreter.

Deactivate command if needed:

```powershell
deactivate
```

Delete venv on Windows PowerShell:

```powershell
Remove-Item -Recurse -Force .venv
```

---

### Step 4 — Upgrade pip Inside the Virtual Environment

```powershell
python -m pip install --upgrade pip
```

Expected: the final line reads something like `Successfully installed
pip-XX.X.X` or `Requirement already satisfied: pip`.

---

### Step 5 — Install Dependencies

```powershell
pip install -r requirements.txt
```

Expected: the final line reads something like:

```
Successfully installed imbalanced-learn-0.11.0 joblib-1.3.2 jupyter-1.0.0 ... xgboost-2.0.0
```

Runtime: 3 to 8 minutes on a typical machine. It may take longer on
a slow connection.

If pip fails during a wheel build, the most common cause is that the
Python version inside `.venv` is not 3.11.9. Confirm with
`python --version`. If the version is wrong, return to Step 3.

### Step 7 — Generate the Processed Data

This is the step that produces `data/processed/`.

The processed data is generated by running one notebook top to bottom.
It takes 3 to 5 minutes.

```powershell
jupyter notebook notebooks/01_EDA_and_Data_Prep.ipynb
```

In the Jupyter interface:

1. Confirm the kernel is `Python 3` from the `.venv`. The kernel name
   in the top-right corner should show `Python 3` and the path should
   point into the repository's `.venv`.
2. Run every cell in order, top to bottom.
3. Do not skip cells.
4. Do not stop partway.
5. Wait for the final summary cell (the last cell in the notebook) to
   complete. It prints a table of counts and a completion line.

When the notebook finishes, the last cell's output includes a
listing similar to:

```
Artifacts written to: C:\Users\<user>\...\network-guardian-ids\data\processed
  class_order.json
  correlation_matrix.csv
  encoder_onehot_protocol_flag.pkl
  encoder_service.pkl
  feature_names.json
  scaler_tabnet.pkl
  split_indices.json
  test_preencoded.csv
  train_preencoded.csv
  X_test.npy
  X_train.npy
  y_test.npy
  y_train.npy
```

If a cell fails, stop. Do not retry. Copy the full traceback and post
it in the team channel. Do not attempt to fix the code.

If the notebook finishes but `data/processed/` is still missing the
`.npy` files, the notebook did not run to completion. Check the last
cell output for a partial list.

### Step 9 — Verify the Frozen Hashes

```powershell
python -c "
from src.utils import compute_file_sha256, PATHS
expected = {
    'class_order.json':   '63b3d7da8141a720abd0fb006c5ab285b4d4f6c2068bcc67304c35a40d08f52a',
    'split_indices.json': '6b1272a7063348b1ba26ce60be2a6c492df6464fb228e1eb42e452011971f5db',
    'feature_names.json': 'd014bf4733de5e439169d5a5d346be4a0c2bef8080379ef27da6149357f2cef8',
}
for name, exp in expected.items():
    actual = compute_file_sha256(PATHS.processed / name)
    status = 'OK' if actual == exp else 'MISMATCH'
    print(f'{name:<24} {status}')

models_hash = compute_file_sha256(PATHS.repo_root / 'src' / 'models.py')
expected_models = '38c8e622642e2f77cefe9b704639e9c1fb448d46dde2453876175feefbaa4d2d'
status = 'OK' if models_hash == expected_models else 'MISMATCH'
print(f'{\"src/models.py\":<24} {status}')
"
```

Expected output, exactly four lines:

```
class_order.json         OK
split_indices.json       OK
feature_names.json       OK
src/models.py            OK
```

If any line prints `MISMATCH`, stop and post the output in the team
channel with `@Kit`. Do not proceed. Do not attempt to fix the code.

Common causes of `MISMATCH`:

1. `src/data_prep.py` or `src/encoding.py` has uncommitted local
   changes. Run `git status --short` and inspect.
2. `data/raw/kddcup.csv` was modified. Run `git status --short`.
3. You are on the wrong branch. Run `git branch --show-current` and
   confirm you are on the branch Kit announced in the team channel.

## 4. Common Problems

### "The `data/processed/` directory does not exist"

You skipped Step 7. Run Notebook 01.

### "I ran Notebook 01 but `data/processed/` is still empty"

Notebook 01 did not complete. Check the last cell output for a
partial listing. Re-run the notebook from the beginning.

### "Hash verification prints `MISMATCH`"

See Step 9. Stop, post the output, tag Kit.

### "`python --version` prints a version other than 3.11.9"

You are using the wrong interpreter. Deactivate, delete `.venv`, and
repeat Step 3 with `py -3.11`.

### "pip install fails during a wheel build"

The Python version inside `.venv` is not 3.11.9. Confirm with
`python --version`. If wrong, return to Step 3.

### "I ran Notebook 01 twice; did I break anything?"

No. The pipeline is deterministic. The split uses a fixed seed. Running
Notebook 01 twice produces byte-identical output. The hashes will
still print `OK`.

### "My `models/` directory is empty"

Expected until Notebook 02 Cell 6 (Amber), Cell 8 (Kenneth), or Cell
10 (Dwayne) completes. Before those, `models/` is empty by design.

### "I see `data/processed/*.npy` in `git status` as untracked"

Expected. The `.gitignore` policy excludes these files from version
control. Do not `git add` them. Do not commit them.

### "I see `data/processed/class_order.json` listed as untracked"

This should not happen. That file is tracked. If it appears as
untracked, the file was deleted locally and then regenerated by
Notebook 01 with a different path. Stop and report to Kit.

### "`git push` fails with `GH013: Repository rule violations`"

Your push is being rejected by GitHub's branch protection rule.

- If you are pushing to `main`: this is expected. Open a pull request.
- If you are pushing to your own feature branch: report to Kit. The
  rule may be misconfigured. See
  `docs/contracts/branch_protection_policy.md`.

### "I cannot find `docs/contracts/role-5-training-execution-spec.md`"

The file is committed on the branch Kit announced. Confirm your branch:

```powershell
git branch --show-current
```

If you are on `main` and the file is missing, pull the latest:

```powershell
git checkout main
git pull origin main
```

If it is still missing, the branch containing the file has not been
merged yet. Ask Kit which branch to check out.

## 5. Order of Operations

The pipeline is sequential. Every stage depends on the previous one.

```
1.  Clone the repository
2.  Confirm Python 3.11.9 is available
3.  Create the virtual environment
4.  Upgrade pip
5.  Install dependencies
6.  Verify the environment (src/verify_env.py)
7.  Run Notebook 01 → generates data/processed/
8.  Verify data shapes
9.  Verify frozen hashes
10. Run your assigned cells in Notebook 02 → generates models/
11. Wait for the other roles' models to complete
12. Run Notebook 03 (Dwayne) → generates outputs/03_evaluation/
13. Markie writes the paper using the outputs
14. Kenneth produces the video
```

You cannot skip a step. You cannot run out of order. If a prerequisite
is missing, the downstream step fails.
