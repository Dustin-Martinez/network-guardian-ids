# Backend Bridge

From the repository root, complete `docs/SETUP.md`, then:

```powershell
npm ci --prefix server
npm start --prefix server
```

The API listens at `http://localhost:5000/api/analyze`. The server uses the repository `.venv` interpreter; shell activation is optional. Obtain the selected model and its matching `.meta.json` from the owning member. Random Forest and XGBoost use `models/rf_baseline.joblib` and `models/xgb_optuna.joblib`, respectively.

In a second PowerShell terminal at the repo root:

```powershell
$packet = Get-Content .\server\examples\normal-smtp.json -Raw | ConvertFrom-Json
$packet | Add-Member -NotePropertyName model -NotePropertyValue random_forest
Invoke-RestMethod -Uri http://localhost:5000/api/analyze -Method Post -ContentType application/json -Body ($packet | ConvertTo-Json)
```

Success returns prediction, confidence as a percentage, is_threat, and model. Invalid requests return HTTP 400. Missing or incompatible artifacts, bridge crashes and timeouts return HTTP 500. Always check the error field and HTTP status. The default fields in an error response must never be displayed as a successful prediction.

Amber's frontend already targets this URL. During frontend Phase 3, disable USE_MOCK and select an available model. Default selection is XGBoost; choose Random Forest until XGBoost's artifacts are supplied. The backend never substitutes mock predictions.

TabNet is guarded until the scaling mismatch between its training implementation and the API contract is resolved by Kit. See `docs/reports/role-2-phase-2-markie-backend-bridge.md` and the linked decision record.

## Checks

```powershell
npm test --prefix server
.\.venv\Scripts\python.exe -m unittest discover -s server/tests -p test_bridge.py -v
```

Python feature tests require the actual frozen preprocessing artifacts generated by Notebook 01. HTTP failure-path tests use dedicated subprocess fixtures; these are not used by the real route.
